BOKA COCKPIT — Architektura Organizmu Multi-Modelowego
Wielomodelowe środowisko myślowe sterowane głosem. Każdy prompt rozchodzi się równolegle na 4 role-modeli, aggregator podejmuje decyzję, pamięć jest włączana tylko gdy trzeba. 8 warstw, 1 panel kontrolny.
Default to stateless · Elevate to memory only when needed
1 🎙️ VOICE LAYER — Warstwa wejścia Superwhisper · ASR
Superwhisper → tekst Lokalny Whisper (medium/large-v3) zamienia mowę na tekst w czasie rzeczywistym. /api/asr
Parser komend głosowych Wykrywa intencje: „tryb szybki”, „tryb pamięć”, „tryb projektu”, „zapisz to”, „porównaj modele”. IntentParser
Routing intencji Wybór trybu pracy + kierunek do backendu (TEMP / MEMORY / PROJECT). → Orchestrator
↓
2 🧠 ORCHESTRATOR — Core System Next.js API · FastAPI-style
Intent Parser Dekoduje prompt + tryb + tagi. Decyduje czy pamięć jest potrzebna. /api/orchestrator
Mode Selector 🟢 TEMP · 🟡 MEMORY · 🔴 PROJECT. Determinuje koszt, kontekst i persistencję. 3 tryby
Memory Retrieval Gdy MEMORY/PROJECT: pobiera top-k kontekst z lokalnej bazy JSON + tagów. opcjonalnie
Multi-Model Dispatcher Równoległe wysłanie promptu do 4 modeli przez OpenRouter. Kontrola kosztów i timeoutów. Promise.all
↓
3 🧬 MODELE — Multi-Provider via OpenRouter 4 role
🧭 Kimi 2.7 — Strateg Szybkie myślenie, planowanie, szybkie porównania, intuicyjne skoki. strategy
🔍 DeepSeek R1 — Krytyk Analiza ryzyka, luki w argumentacji, alternativa perspective. critique
⚙️ GLM-5.2 — Wykonawca Kod, struktura, konkretne kroki implementacji, techniczne detale. execution
⚖️ Claude Opus 4.8 — Sędzia Finalna synteza, ważona decyzja, confidence scoring. judge
↓
4 🧮 AGGREGATOR — Decyzyjny rdzeń Scoring · Weighted Vote
Confidence scoring Każda odpowiedź modelu dostaje 0.0–1.0 na podstawie spójności i ostateczności. 0.0 – 1.0
Weighted vote Wagi ról: strateg 0.25 · krytyk 0.25 · wykonawca 0.25 · sędzia 0.25 (domyślnie równe). Σ w_i · c_i
Final decision Sędzia Claude Opus wybiera jedną odpowiedź lub syntezyje je w jedną decyzję końcową. → UI
↓
5 🧠 MEMORY SYSTEM — Dwa poziomy JSON store · Vector-ready
🔹 MEMORY TEMP (default) Brak zapisu. Kontekst tylko w jednym promptcie. Reset po zadaniu. stateless
🔹 MEMORY LONG-TERM (toggle) Zapis decyzji, wniosków, projektów. Retrieval po tagach i timestampie. stateful
Struktura rekordu {timestamp, topic, input, outputs{kimi,deepseek,glm}, final_decision, confidence, tags[]} JSON
↓
6 🔁 TRYBY PRACY — UX core 3 modes
🟢 MODE 1 — TEMP Brak pamięci · 2–4 modele · krótki output. „Zrób szybkie porównanie X”. default
🟡 MODE 2 — MEMORY Pobiera kontekst · porównuje z historią. „Pracujemy nad tym projektem dalej”. refleksja
🔴 MODE 3 — PROJECT Pełna pamięć · zapis każdej decyzji · iteracyjna poprawa. „To jest mój system”. rozwój
↓
7 🗣️ VOICE COMMANDS — Sterowanie głosem Superwhisper triggers

Operacje „porównaj modele” · „wybierz najlepszą odpowiedź” · „zapisz to” · „przypomnij co ustaliliśmy” actions
Hands-free Działa bez przełączania okien — mówisz, Boka odpowiada głosem (TTS) + tekstem. no-window-switch
